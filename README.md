# Nexus Loop

A quality-control loop for an already-deployed AI support agent: it reads the
agent's logs, finds what broke, explains why, proposes a small fix, verifies the
fix on a replay service, and gives a human one decision to make.

Two things are submitted:

1. **`loop-report.json`** — generated by the system, valid against
   `tools/nexus-loop-kit/schema/loop-report.schema.json`, produced unedited from
   the sealed run.
2. **One screen** — a finding, the evidence behind it, and a working
   **APPROVE / REJECT** control that writes the human decision back into the
   report.

Plus a one-page note: what is real, what is stubbed, what breaks at 100×
(`docs/submission-note.md`).

Two rules cannot be broken: never ask a language model for a fact the logs
already record, and never change the yardstick (metric definitions, judge
versions, the reviewed set of good conversations) to make a result look better.

Everything is on `master`:

  practice corpus and passes every held-out corpus the testbed throws at it —
  the six-corpus sealed pool (6/6), the moved-fault corpus (55), and the

## Quick start

### Run the solution (produce the report)

```bash
# start the replay service in another shell
python3 tools/nexus-loop-kit/replay/serve.py --kit kit --port 8719

# cold run: one command, unattended
python3 run.py --kit kit --team demo --out out/loop-report.json
```

With no replay service running, add `--no-replay` and the report is still valid
(verifications are simply omitted). Score it against the practice key:

```bash
python3 tools/nexus-loop-kit/score.py \
  --report out/loop-report.json \
  --ground-truth kit/ground_truth/ground_truth.json
```

Outputs land in `out/`: `loop-report.json`, `golden_set.json`, `replay.log`, and
`decisions.log` once a human decides.

### Open the decision screen

```bash
python3 -m nexus_loop.app --report out/loop-report.json --port 8765
# then open http://127.0.0.1:8765
```

Or run both in one process:

```bash
python3 run.py --kit kit --team demo --out out/loop-report.json --serve --port 8765
```

The screen renders only from the report; the approve/reject action writes back
into `prescriptions[].approval` atomically. See **`docs/ui-handoff.md`** for the
field contract, **`docs/ux-psychology.md`** / **`handoff.md`** for why the
console is shaped that way, and **`docs/manager-english.md`** for the jargon →
manager-English glossary used on the page.

**Generate report (operator header):** when the screen is started with
`--allow-generate` / `NEXUS_LOOP_ALLOW_GENERATE=1`, or via `run.py --serve`,
`POST /generate` re-runs `run.py` into the same report path (default
`--no-replay`; optional `--with-replay` / `NEXUS_LOOP_REPLAY_URL`). The header
button triggers that path and reloads `/report.json`. Without the flag,
generation stays off (403) so a plain `python3 -m nexus_loop.app` never shells
out unexpectedly.

**Replay service (what this repo uses):** the pipeline does **not** embed a
replay backend. `run.py` optionally calls the kit’s provided service
(`tools/nexus-loop-kit/replay/serve.py`) through the client in
`nexus_loop/replay.py` (`POST {url}/replay`). Successful replies become
`verifications[]` via `nexus_loop/report.py` `attach_verifications`. With
`--no-replay` or an unreachable endpoint, the report stays valid with an empty
`verifications` list. The operator screen does not call replay itself; it only
renders report fields — including the **Did the test help** span and before/after
bars from `verifications[]` (`nexus_loop/static/index.html`).

The desk is a sunken `#F7F8F9` canvas with raised rounded cards. Type is
exactly two families: Newsreader (claims, span headings, and technical jargon
such as Technical names / codes / paths) and Source Sans 3 (chrome, KPI
figures, and buttons), with Iowan/Palatino and Segoe
fallbacks — no separate monospace stack. The gate is a traffic
light: green Accept `#1F845A`, red Reject `#C9372C`, grey Defer, equal
targets, required reason. Finding groups sit on a top mode bar above the three
panes: **Needs attention** / **Dismissed signals** / **No measurement**;
**Needs attention** is danger red, the same token as the regression dots. The
left list is rows only; ArrowUp/ArrowDown (plus Home/End) move the selection.
On **Dismissed signals** or **No measurement**, the gate shows an idle line
only — “Nothing to approve. This is not a problem.” or “Nothing to approve. We
will not invent a failover rate.” Detector codes sit in a **Technical names**
footer pinned at the bottom of the story pane. Impact KPIs sit on a 5-column
strip (label / figure / caption): conversations info, would-have-resolved warn,
handoffs/abandoned bad, cost warn. Mode labels, idle gates, ledes, and row
copy are catalogued in **`docs/manager-english.md`**.

### Copy decision note (after the verdict)

Once a Needs attention finding has a recorded decision in the loaded report,
the decision panel shows **Copy decision note**. It puts a paste-ready hand-off
on the clipboard: the verdict and target, the finding and slice, the reason
verbatim, who decided and when, what moved, the downstream impact, the fix,
the risk if wrong, and a deep link. Accept, Reject, and Defer get the same
control. Nothing appears before the save.

The Decisions tab offers **Copy all decisions** once any decision exists: one
summary of every verdict, the dismissed-signals count, and the refusal claims.
The note is built in `nexus_loop/static/app.js` from the report only.

The top bar also offers **Generate report** when the server was started with
generate enabled; it POSTs `/generate` to re-run the pipeline into the same
report and reloads. Psychology: **`handoff.md`**.

### Run the testbed

```bash
python3 tools/testbed/make_corpora.py --out-dir /tmp/nexus-testbed/pool \
  --secrets pool-alpha,pool-bravo,pool-charlie
python3 tools/testbed/make_corpora.py --out-dir /tmp/nexus-testbed/pool \
  --secrets hard-alpha,hard-bravo,hard-charlie --rename
python3 tools/testbed/evaluate.py \
  --candidates tools/testbed/candidates.json \
  --kits-dir /tmp/nexus-testbed/pool --quick --explain \
  --json-out /tmp/nexus-testbed/result.json \
  --matrix-out /tmp/nexus-testbed/matrix.md
```

See **`tools/testbed/README.md`** for the candidate contract, every check, the
pass criteria, the point ledger, and the moved-fault generator.

## The solution in one paragraph

`run.py` loads the kit, folds step-level facts down to one row per session,
computes per-tenant emission coverage, runs three detector-specific analyses
(silent tool contract break, KB gap, prompt/efficiency regression), examines and
dismisses three lookalikes (traffic mix, load event, judge-version boundary),
answers the eleven operator asks as metrics or gaps, mines a "good" standard and
freezes a golden set, assembles a schema-valid report of findings, diagnoses,
impact and decision-shaped prescriptions, verifies one fix on the replay
service, and serves a decision screen. Deterministic Python throughout; no LLM
is called for any logged fact. Full detail: **`docs/solution-overview.md`**.

## Conventions

- Documentation lives in `docs/`; tooling lives in `tools/`.
- Generated outputs (e.g. `out/`) are gitignored and are not deliverables.
- The submission is the generated report plus the screen; never hand-edit the
  report to improve a score.
- Keep kit data and organiser tooling unchanged.
